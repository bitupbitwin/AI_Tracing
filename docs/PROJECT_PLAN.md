# AI 大模型信息追踪项目开发计划书

## 1. 项目背景

AI 大模型发布节奏快，模型能力、开源状态、订阅价格、API 价格和优惠政策经常变化。为了持续追踪主流模型，需要一个可重复运行的 Python 脚本，把官方来源和可选搜索结果汇总为 Markdown 文档，方便提交到 GitHub 仓库沉淀历史记录。

## 2. 项目目标

1. 自动汇总已发布 AI 大模型的核心信息。
2. 输出字段包括厂商、模型名称、官方地址、CLI/Agent 支持、插件/工具支持、Web 端、开源/闭源状态、许可证/权重/商用限制、优惠信息、订阅包月价格、订阅包年价格、API 调用价格、模型特点、多模态能力、model card、release note 和来源链接。
3. 生成 Markdown 报告，默认输出到 `reports/ai_model_report.md`。
4. README 提供项目说明、运行方式、数据源维护方式和后续扩展方案。

## 3. 功能范围

### 3.1 必做功能

1. 读取 `data/model_sources.json` 中配置的模型厂商、模型系列和官方来源。
2. 抓取官方模型页、价格页、订阅页、model card 和 release note。
3. 自动提取页面中的价格、包月/包年、优惠、开源和多模态关键词。
4. 生成结构化 Markdown 汇总表。
5. 保留来源链接、官方地址、抓取状态和生成时间，方便人工复核。
6. 追踪官方 CLI/Agent 软件、插件/工具能力、Web 端入口和官方文档地址。

### 3.2 可选增强

1. 通过 `SERPAPI_KEY`、`BING_SEARCH_API_KEY` 或 `TAVILY_API_KEY` 自动发现更多来源。
2. 增加 CSV/JSON 输出，便于后续做可视化。
3. 增加定时任务，每日或每周生成报告并提交。
4. 增加模型价格变动对比，输出涨价、降价和免费额度变化。

## 4. 数据字段设计

| 字段 | 说明 |
| --- | --- |
| 厂商 | 模型归属公司或平台 |
| 模型/系列 | 例如 GPT、Claude、Gemini、Qwen、Llama |
| 官方地址 | 官方产品页、聊天入口或开发者入口 |
| CLI/Agent | 是否支持官方 CLI、Coding Agent、Agent 软件或第三方 Agent 接入 |
| 插件/工具 | 是否支持官方 tools、插件、MCP、function calling 或扩展 |
| Web 端 | 官方 Web 应用入口 |
| 开源状态 | 开源、开放权重、闭源或混合 |
| 许可证/权重/商用 | 开源许可证、权重仓库、商用限制和服务条款 |
| 多模态 | 是否支持图像、音频、视频、工具调用等能力 |
| 特点 | 长上下文、推理、代码、私有化部署等核心卖点 |
| Model Card | 官方 model card、模型文档或权重仓库 |
| Release Note | 官方 release note、博客、changelog 或发布公告 |
| 订阅价格 | 包月、包年、会员套餐等用户侧价格 |
| API/调用价格 | 输入、输出、缓存、图片、音频等调用计费 |
| 优惠 | 免费额度、试用额度、折扣和促销 |
| 抓取状态 | 成功抓取来源数量或失败情况 |
| 来源 | 官方链接和搜索发现链接 |

## 5. 技术方案

1. 使用 Python 标准库实现命令行脚本，降低部署门槛。
2. 使用 JSON 维护可扩展的数据源配置。
3. 使用 `urllib` 抓取网页，使用 `html.parser` 提取正文文本。
4. 使用正则表达式和关键词规则提取价格、订阅、优惠、多模态、Agent、插件和工具调用信息。
5. 输出 Markdown 表格，便于直接在 GitHub 查看。

## 7. 运行方式

```bash
python ai_model_tracing.py
```

仅使用配置数据、不联网抓取：

```bash
python ai_model_tracing.py --no-fetch
```

启用搜索发现：

```bash
SERPAPI_KEY=your_key python ai_model_tracing.py --discover
```

## 8. 里程碑

| 阶段 | 交付物 | 验收标准 |
| --- | --- | --- |
| M1 初始版本 | 脚本、数据源、README、计划书 | 可生成 Markdown 报告 |
| M2 数据增强 | 增加更多厂商、模型、官方地址、Agent/插件/Web 字段 | 每条记录有至少一个来源 |
| M3 自动发现 | 接入搜索 API | 能自动补充候选来源 |
| M4 变动追踪 | 生成价格变化对比 | 能识别新增、删除和价格变化 |
| M5 自动发布 | GitHub Actions 定时运行 | 定时生成报告并提交 |

## 9. 验收标准

1. 本地运行脚本后生成 `reports/ai_model_report.md`。
2. 报告中每条模型记录包含来源链接。
3. README 能让新用户理解如何运行、如何配置数据源、如何开启搜索发现。
4. 价格字段不能无来源硬编造；抓取不到时应标记为需查看来源。
5. 对开源模型必须记录许可证、权重地址和商用限制的复核状态。
6. 对 CLI/Agent、插件/工具、Web 端能力必须记录官方地址或标记为未确认。

## 10. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 价格页面频繁改版 | 保留来源链接，抓取失败时不伪造价格 |
| “所有模型”范围过大 | 先覆盖主流厂商，再通过配置持续扩展 |
| 搜索结果质量不稳定 | 默认只使用官方来源，搜索发现结果需人工复核 |
| 不同厂商计费口径不同 | 在报告中保留原始价格片段和来源 |
| GitHub 自动提交权限不足 | 先生成本地文件，再配置仓库写权限或 GitHub Actions |
